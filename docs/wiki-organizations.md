# RP 조직 자동 틀 작성법

## 봉누도 시즌2: 전체 시민 원본과 참조 표

봉누도 시즌2는 아래 통합 방식으로 작성한다. 하단의 3열 작성법은 다른 문서의 기존 틀과 호환된다.

- `_wiki/wiki-nambong-island-2.md`의 `봉누도 시민 전체 (등급순)` 표만 기본 정보의 원본이다. 시민 등급, 방송인·채널, RP 이름, 소속, RP·컨셉 요약, 특이사항, 직책, 진급 기록, 조직 내 평판·역할의 9열을 유지하고 `{: .wiki-citizen-source }`로 지정한다. 표시 순서는 빌드 시 아래 규칙대로 정리된다. 이전 10열 원본도 읽을 수 있지만 참여 상태는 특이사항으로 옮겨 표시한다.
- 다른 표는 `RP 이름 | 특이사항`의 2열만 작성하고 include에 `source="citizens"`를 붙인다. 원본이 문서 뒤에 있어도 빌드할 때 연결되며, 브라우저에서 별도 데이터를 가져오지 않는다. 공통 특이사항에 각 표의 특이사항이 추가된다.
- `layout="citizen"`은 시민용 6열, `layout="service"`는 공무직용 7열, `layout="gang"`은 정식 갱단용 7열, `layout="crew"`는 결성 준비 크루용 7열을 만든다. 공무직은 1등급, 정식 갱단은 3등급만 허용한다. 임시 크루는 현재 등급을 유지한다.
- 직책은 원본에서 `봉누도시청: 가이드; 봉누도방송국: 기자`처럼 **틀의 title과 일치하는 조직명: 직책**으로 쓴다. 단일 직책은 조직명 없이 적어도 된다. 진급 기록·평판·RP 요약도 원본에서 관리한다. 전체 표의 직책 칸에는 조직명을 반복하지 않고 직책만 표시하며, 셀에 마우스를 올리면 조직별 원문을 확인할 수 있다.
- RP 이름의 공백은 참조 시 무시한다. RP 이름이 `—`인 사람은 `@꽃빈`처럼 방송인 이름으로 참조한다. RP 이름이 확인되면 원본과 해당 참조 이름을 함께 바꾼다. 없는 이름, 중복 이름, 잘못된 등급은 빌드를 실패시킨다.
- 원본의 방송인 칸이 `가이드` 또는 `운영자`인 사람과 특이사항에 `참여 종료`가 있는 사람은 현재 참여자 합계에서 제외한다. `참여 중`은 표시하지 않으며, 나머지 상태는 특이사항에 적는다. RP 이름이 비어 있으면 `현재 미접속/RP 이름 없음`을 특이사항에 표시한다. RP 이름을 등록할 때 원본의 해당 문구도 제거한다. 원본에는 역사 기록을 남기고, 크루의 `멤버 미확정`은 특이사항에 기재하며 확정 인원과 구별한다.
- 알 수 없는 RP 설정·진급·역할은 `—`로 둔다. 준비 크루 이름의 첫 인물을 임의로 대표로 지정하지 않는다.
- 표 머리글 버튼은 선택한 열을 오름차순·내림차순으로 정렬한다. 원본 파일 순서나 다른 표는 바뀌지 않는다.
- 표시 순서는 공무직·갱단·크루에서 `직책 → RP 이름 → 방송인·채널 → RP·컨셉 요약 → 진급 기록 → 조직 내 평판·역할 → 특이사항`, 시민에서 `RP 이름 → 방송인·채널 → RP·컨셉 요약 → 시민 등급 → 소속 → 특이사항`이다. 전체 원본 표는 직책부터 시작하는 9열이며 시민 등급 다음에 소속, 특이사항은 마지막이다.
- 소속 칸에는 `경찰`, `봉누도경찰청`, `EMS`, `봉누도시청`, `방송국`, `교통정비공사`, `무소속`처럼 이름만 적으면 SVG 아이콘과 원래 이름이 함께 나온다. 복수 소속은 `<br>`로 구분한다. 알려지지 않은 소속도 이름을 보존하고 일반 조직 아이콘을 붙인다. 아이콘은 장식용이므로 검색·정렬과 스크린리더가 읽는 이름에는 영향을 주지 않는다.
- 열 너비는 내용에 따라 바뀌지 않는 `colgroup` 비율로 지정한다. 직책 5자, 시민 등급 4자, RP 이름 8자, 소속 7자, 특이사항 5자를 기준으로 여백과 아이콘 공간을 확보한다. 방송인 열은 RP 이름보다 조금 넓고, RP 요약은 방송인 열과 같으며, 진급·평판 열은 방송인 열의 1.2배다.
- PC에서는 표가 주어진 본문 너비 안에 들어가도록 글자 크기를 조정한다. 900px 이하에서는 14px 기본 글자 크기와 열 너비를 유지하고 표 영역에서만 가로 스크롤한다. 방송인·RP 요약·진급·평판 본문은 기본 크기의 88%로 표시한다. 행 음영, 키보드 포커스 강조, 모바일 RP 이름 열 고정을 제공한다. 좁은 PC 창(901~1399px)에서는 이 명단이 있는 문서의 메뉴를 상단으로 배치해 표 너비를 확보한다.
- 추천 시점도 같은 `source="citizens"` 표를 사용하므로 채널·직책·진급 내용이 원본과 함께 갱신된다. `title`은 원본 직책의 조직명과 일치시키고, 추천 표라는 설명은 `subtitle="다시보기·라이브 추천 시점"`에 쓴다.
- 모든 위키 문서에 페이지 내 검색과 표별 검색이 제공된다. 입력 시에만 해당 범위를 검색하며, 이전/다음(Enter/Shift+Enter)으로 이동하고 종료/Escape/검색어 지우기로 접힘 상태를 복원한다. 동시에 한 검색 범위만 활성화된다. 검색 중 직접 바꾼 접힘 상태는 유지된다.

```liquid
{% capture roster %}
| RP 이름 | 특이사항 |
| --- | --- |
| 황천길 | — |
| 오구라 함마 | 멤버 미확정 |
{: .wiki-service-table }
{% endcapture %}
{% include wiki-template.html name="임시크루명단" title="예시 크루" icon="gang" source="citizens" layout="crew" body=roster %}
```

검증: `ruby scripts/test-wiki-citizens.rb`, 기존 위키 테스트, `jekyll _3.10.0_ build`. 시민 원본 228명은 현재 참여자 219명, 가이드·운영자 8명, 참여 종료 1명으로 구성된다(2026-09-16 입력 명단 기준). 이 집계는 서버 접속 상태를 실시간 조회한 값이 아니다.

브라우저 회귀 검증은 빌드 후 `scripts/test-wiki-find.html`을 `_site/test-wiki-find.html`로 복사하고 로컬 서버의 `/test-wiki-find.html`을 Chrome에서 연다. 하단에 `ALL PASSED`가 표시되어야 한다. 테스트 파일은 배포 빌드에서 제외된다.

공무직·사업체·갱단·정당은 같은 조직 틀을 사용한다. 직책과 명단은 해당 위키 Markdown 문서에서 관리하며 템플릿에는 특정 서버의 직급·인원·평판 규칙을 넣지 않는다.

## 기본 작성

```liquid
{% capture roster %}
| 직책 | 소속 인원 | 진급 기록 |
| :--- | :--- | :--- |
| 대표 | 예시인물[+예시방송인] | 2026-09-15: 대표 취임 |
| 직원 | 안내인[+가이드]<br>다른인물[+다른방송인] | — |
| 수습 | — | — |
{: .wiki-service-table }
{% endcapture %}
{% include wiki-template.html name="조직명단" title="조직 이름" icon="business" period="2026-09-15 ~" as_of="2026-09-15" status="활동 중" body=roster %}
```

- 맨 위 한 행에 SVG 아이콘·기관 명칭을 표시하고 세 열을 합친다. 영문명(`subtitle`), 활동 기간(`period`), 상태(`status`), 명단 기준일(`as_of`)은 선택 사항이다.
- 각 직책 첫 열은 `직책` 아래에 `n명`이 자동 표시된다. 해당 직책의 가이드·운영자도 포함한다.
- 맨 아래 `총 2명 (가이드·운영자 포함 3명)`처럼 참가자 수와 전체 수를 표시한다.
- 빈칸, `-`, `—`는 0명이다. 미확인 인원은 이름을 추측해 넣지 말고 기록 칸에 적는다.
- 두 번째 열은 **한 항목에 한 사람**, 여러 사람은 `<br>`로 구분한다. `<br/>`, `<br />`도 지원한다. Markdown 링크·기존 RP 표기·이스케이프한 파이프(`\|`)를 유지한다.
- 가이드·운영자는 `이름[+가이드]`, `이름[+운영자]`로 표기해야 참가자 합계에서 제외된다. 일반 이름/링크만 쓴 항목은 참가자 한 명으로 센다. `가이드북` 같은 방송인 이름은 제외하지 않는다.
- 줄바꿈은 인원 구분에만 쓴다. 설명·날짜·퇴사자·겸직은 세 번째 열에 쓴다. 세 번째 열 제목은 `진급 기록`, `변동 기록`, `임명·선거 기록` 등으로 자유롭게 바꿀 수 있다.
- 진급 시 현재 명단에서 기존 직책의 인물을 새 직책으로 옮기고, 기록 칸에 인물·날짜·이전 직책·변경 내용을 남긴다. 이전 기록은 삭제할 필요가 없다. 별도 날짜 근거가 없는 인원에게 날짜를 만들지 않는다.
- 동일 조직에 같은 RP 이름이 두 번 나오면 빌드를 실패시켜 중복 합계를 막는다. 겸직은 대표 직책에 한 번만 기재하고 나머지는 기록 칸에 적는다. 동명이인은 `{이름 (구분자)}[+방송인]`으로 구분한다. 다른 조직에서 같은 인물이 활동하는 것은 허용한다.
- 전체 서버 참가자 수는 조직별 합계를 단순히 더해서 계산하지 않는다. 겸업·정당 활동 등으로 중복 소속될 수 있다.
- 숫자를 적는 `members` 인수는 더 이상 사용하지 않는다. 본문의 과거 날짜별 인원 설명은 자동 합계와 별개인 역사 기록이다.

집계는 Jekyll 빌드 시 Markdown 구문 트리에서 실행한다. JavaScript 없이도 표시되며 검색 색인에도 반영된다. 표는 반드시 세 열이며 `{: .wiki-service-table }`로 지정한다. 한 틀에는 명단 표를 하나만 둔다. 좁은 화면은 표 영역에서 가로 스크롤하며 키보드로도 접근할 수 있다.

## 아이콘과 별칭

### 무소속 시민

시민에게는 직급을 만들지 않고 `RP 이름 | 방송인·채널 | 참여·변동 기록`을 사용한다. 한 사람당 Markdown 표 한 행만 작성하면 RP 이름 확인/미확인 분류와 인원 수가 자동으로 만들어진다.

```liquid
{% capture citizen_roster %}
| RP 이름 | 방송인·채널 | 참여·변동 기록 |
| :--- | :--- | :--- |
| 예시인물 | [치지직:채널ID]{예시방송인} | 1일차 추합 |
| — | [치지직:다른채널ID]{다른방송인} | — |
{: .wiki-service-table }
{% endcapture %}
{% include wiki-template.html name="시민명단" title="무소속 시민" body=citizen_roster %}
```

- 첫 열이 빈칸, `-`, `—`이면 RP 이름 미확인으로 분류한다. 이름을 채우면 확인 분류로 자동 이동하며 전체 인원은 유지된다.
- 두 번째 열은 방송인 한 명 또는 그 채널 링크만 쓴다. 세 번째 열은 추가 합격·소속 이동·참여 종료 기록용이며 집계하지 않는다.
- 분류마다 `n명`, 하단에는 `총 n명 (RP 이름 확인 n명 · 미확인 n명)`을 표시한다. 비어 있는 분류도 0명으로 표시한다.
- 이름 확인 여부는 실제 온라인 상태를 조회한 결과가 아니다. 미접속·미기록 등으로 RP 이름이 없는 참가자는 미확인에 둔다. 임의의 RP 이름이나 평판을 부여하지 않는다.
- 같은 분류 안에서는 문서의 행 순서를 유지한다. 방송인 이름순으로 작성하면 화면에서도 해당 순서를 유지한다.
- 공무직·사업체 등으로 소속이 변경된 인물은 현재 시민 명단에서 제거하고 소속 명단으로 옮긴다. 추가 합격·소속 이동 날짜는 근거가 있을 때만 적는다.
- 중도하차·밴 기록은 **별도 시민명단 틀**로 작성한다. 각 틀은 자기 명단만 집계하므로 현재 시민 합계에 섞이지 않는다. 추천 시점 틀 역시 전체 시민 명단의 부분집합으로 별도 집계한다.
- 본문의 역사적 인원 기록과 현재 명단 수가 다를 때는 자동 합계에 맞춰 사람을 만들어 넣지 않는다. 차이와 확인 필요성을 기록한다.

2026-09-16 기준 시민 명단은 현재 시민 165명(이름 확인 158명, 미확인 7명), 참여 종료 1명이다. 사용자가 제공한 기준 목록과 대조해 누락된 `쌀먹쥐`를 추가했으며, RP 이름이 기록되지 않은 7명은 미확인으로 분류한다. 본문의 과거 시점 인원 기록(156명)과 현재 자동 합계(165명)는 서로 다른 기준일을 가리킨다.

### 기관·조직

`공무직명단`은 호환용 별칭이고, `조직명단`, `사업체명단`, `갱단명단`, `정당명단` 모두 동일한 구조를 쓴다. 별칭과 아이콘은 독립적이므로 `icon`을 함께 지정한다.

| icon | 도안 | 사용 예 |
| --- | --- | --- |
| city | 관청 기둥 | 시청 |
| police | 별이 있는 방패 | 경찰청 |
| hospital | 의료 십자 | EMS |
| broadcast | 마이크·전파 | 방송국 |
| transport | 정비 렌치 | 교통정비공사 |
| business | 서류 가방 | 사업체 |
| gang | 각진 조직 문장 | 갱단 |
| party | 깃발·체크 | 정당 |
| organization | 조직도 | 기본값, 기타 단체 |
| citizen | 시민 신분증 | 시민명단에서 자동 선택 |

아이콘은 이 저장소에서 직접 제작한 SVG이며 GTA V의 도시 기관 배지를 연상시키는 공통 외곽선을 사용한다. 공식 게임 로고는 사용하지 않는다. 파일은 `assets/icons/organizations/`에 있다. 기관명이 바로 옆에 있어 아이콘은 장식용 빈 대체 텍스트로 처리한다.

## 조사 메모와 설계 근거 (2026-09-15)

### 확인된 자료

- **봉누도1:** 저장소 `_wiki/wiki-nambong-island-1.md`에는 새부리당·시민의 힘·더불어봉누당의 시점 기록이 있다. 이를 근거로 정당 틀을 지원하되, 시즌1 조직을 시즌2에 자동 복사하지 않는다. 정치 참여와 절차를 다룬 [학술 논문 초록](https://www.kci.go.kr/kciportal/landing/article.kci?arti_id=ART003267512)도 검색에서 확인했다.
- **봉누도2:** [공식 평판 문서](https://bongnudo.super.site/평판)는 평판과 시민 등급, 그룹 설립·유지 조건을 설명한다. [갱단 문서](https://bongnudo.super.site/갱단)는 설립·가입 조건과 최대 소속 인원을 따로 설명한다. 두 문서의 설립 평판 설명에는 차이가 있으므로 실제 적용 조건은 최신 공지 확인이 필요하다. 템플릿에서 자동으로 가입 가능 여부를 판정하지 않는다.
- **조직과 소유 사업체 구분:** [공식 불법 사업체 문서](https://bongnudo.super.site/불법-사업체)는 갱단의 사업체 인수와 인원·평판 조건을 별도로 설명한다. 조직과 사업체를 분리하고 소유 관계를 연결해야 직원 명단과 갱단 명단이 뒤섞이지 않는다.
- **다른 FiveM RP 구현:** [QBCore 공식 문서의 Jobs·Gangs](https://github.com/qbcore-framework/qb-docs/blob/main/qb-core/shared.md)는 직업과 갱단 모두에 가변적인 직급 목록을 둔다. [플레이어 데이터](https://github.com/qbcore-framework/qb-docs/blob/main/qb-core/player-data.md)는 직업과 갱단 소속을 별도로 보관한다. 이는 직급을 공통 틀에 고정하지 않고 복수 조직 소속을 허용하는 설계의 참고이며, 봉누도가 QBCore를 사용한다는 뜻은 아니다.

공식 위키는 직접 접근 시 HTTP 403이어서 검색 색인에 노출된 본문(문서 수정일 2026-09-12)을 참고했다. 나무위키 Chrome 접근은 도구의 사이트 보안 정책으로 차단되어 직접 열람하지 못했다. 봉누도2 정당의 게임 내 기능·자격 요건은 이번 조사에서 확인하지 못했다. 정당 틀은 향후 RP 기록용 구조로만 제공한다.

### 다음 단계 제안

1. 조직마다 안정적인 문서 ID, 서버·시즌, 활동 시작·종료일을 두고 명칭 변경은 별칭으로 연결한다.
2. 현재 명단과 날짜별 변경 기록을 분리한다. 탈퇴자·전임자도 사건 기록에서 찾을 수 있게 한다.
3. 평판, 정원, 인수 조건에는 대상과 기준일·출처를 필수로 기록한다. 시즌 변화가 잦으므로 규칙은 공통 코드에 넣지 않는다.
4. 소유 사업체, 동맹, 적대, 연정 등은 방향·기간이 있는 관계로 기록한다. 단순히 같은 조직 분류로 합치지 않는다.
5. 명단이 커지면 캐릭터별 고유 ID를 도입해 같은 방송인의 시즌별 캐릭터와 동명이인을 구분한다. 현재는 Markdown의 RP 이름 단위 중복 검사를 사용한다.

## 외부 기준 목록과 누락 검증

사용자가 받은 최신 명단을 `section|RP 이름|방송인·채널` 형식의 UTF-8 텍스트로 저장한 뒤 다음 명령으로 문서와 대조한다.

```sh
ruby scripts/validate-wiki-roster.rb --wiki _wiki/wiki-nambong-island-2.md --reference roster-reference.txt
```

첫 열은 `city`, `broadcast`, `police`, `hospital`, `transport`, `citizen` 중 하나를 사용한다. 시민의 RP 이름 미확인 인원은 RP 이름 열을 `?`로 적는다. 검증기는 누락·추가·이름/방송인 변경·중복·미확인 수를 보고하고 차이가 있으면 종료 코드 1을 반환한다. 기준 목록은 서버 진행에 따라 날짜별 파일로 보관해 변경 이력을 남긴다.
