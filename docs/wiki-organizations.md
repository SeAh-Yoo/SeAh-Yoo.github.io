# RP 조직 자동 틀 작성법

공무직·사업체·갱단·정당은 같은 조직 틀을 사용한다. 직책과 명단은 해당 위키 Markdown 문서에서 관리하며 템플릿에는 특정 서버의 직급·인원·평판 규칙을 넣지 않는다.

## 기본 작성

```liquid
{% capture roster %}
| 직책 | 소속 인원 | 진급 기록 |
| :--- | :--- | :--- |
| 대표 | 예시인물[+예시방송인] | 2026-09-15: 대표 취임 |
| 직원 | 안내인[+가이드]<br>다른인물[+다른방송인] | — |
| 수습 | — | — |
{: .wiki-service-table }
{% endcapture %}
{% include wiki-template.html name="조직명단" title="조직 이름" icon="business" period="2026-09-15 ~" as_of="2026-09-15" status="활동 중" body=roster %}
```

- 맨 위 한 행에 SVG 아이콘·기관 명칭을 표시하고 세 열을 합친다. 영문명(`subtitle`), 활동 기간(`period`), 상태(`status`), 명단 기준일(`as_of`)은 선택 사항이다.
- 각 직책 첫 열은 `직책` 아래에 `n명`이 자동 표시된다. 해당 직책의 가이드·운영자도 포함한다.
- 맨 아래 `총 2명 (가이드·운영자 포함 3명)`처럼 참가자 수와 전체 수를 표시한다.
- 빈칸, `-`, `—`는 0명이다. 미확인 인원은 이름을 추측해 넣지 말고 기록 칸에 적는다.
- 두 번째 열은 **한 항목에 한 사람**, 여러 사람은 `<br>`로 구분한다. `<br/>`, `<br />`도 지원한다. Markdown 링크·기존 RP 표기·이스케이프한 파이프(`\|`)를 유지한다.
- 가이드·운영자는 `이름[+가이드]`, `이름[+운영자]`로 표기해야 참가자 합계에서 제외된다. 일반 이름/링크만 쓴 항목은 참가자 한 명으로 센다. `가이드북` 같은 방송인 이름은 제외하지 않는다.
- 줄바꿈은 인원 구분에만 쓴다. 설명·날짜·퇴사자·겸직은 세 번째 열에 쓴다. 세 번째 열 제목은 `진급 기록`, `변동 기록`, `임명·선거 기록` 등으로 자유롭게 바꿀 수 있다.
- 진급 시 현재 명단에서 기존 직책의 인물을 새 직책으로 옮기고, 기록 칸에 인물·날짜·이전 직책·변경 내용을 남긴다. 이전 기록은 삭제할 필요가 없다. 별도 날짜 근거가 없는 인원에게 날짜를 만들지 않는다.
- 동일 조직에 같은 RP 이름이 두 번 나오면 빌드를 실패시켜 중복 합계를 막는다. 겸직은 대표 직책에 한 번만 기재하고 나머지는 기록 칸에 적는다. 동명이인은 `{이름 (구분자)}[+방송인]`으로 구분한다. 다른 조직에서 같은 인물이 활동하는 것은 허용한다.
- 전체 서버 참가자 수는 조직별 합계를 단순히 더해서 계산하지 않는다. 겸업·정당 활동 등으로 중복 소속될 수 있다.
- 숫자를 적는 `members` 인수는 더 이상 사용하지 않는다. 본문의 과거 날짜별 인원 설명은 자동 합계와 별개인 역사 기록이다.

집계는 Jekyll 빌드 시 Markdown 구문 트리에서 실행한다. JavaScript 없이도 표시되며 검색 색인에도 반영된다. 표는 반드시 세 열이며 `{: .wiki-service-table }`로 지정한다. 한 틀에는 명단 표를 하나만 둔다. 좁은 화면은 표 영역에서 가로 스크롤하며 키보드로도 접근할 수 있다.

## 아이콘과 별칭

`공무직명단`은 호환용 별칭이고, `조직명단`, `사업체명단`, `갱단명단`, `정당명단` 모두 동일한 구조를 쓴다. 별칭과 아이콘은 독립적이므로 `icon`을 함께 지정한다.

| icon | 도안 | 사용 예 |
| --- | --- | --- |
| city | 관청 기둥 | 시청 |
| police | 별이 있는 방패 | 경찰청 |
| hospital | 의료 십자 | EMS |
| broadcast | 마이크·전파 | 방송국 |
| transport | 정비 렌치 | 교통정비공사 |
| business | 서류 가방 | 사업체 |
| gang | 각진 조직 문장 | 갱단 |
| party | 깃발·체크 | 정당 |
| organization | 조직도 | 기본값, 기타 단체 |

아이콘은 이 저장소에서 직접 제작한 SVG이며 GTA V의 도시 기관 배지를 연상시키는 공통 외곽선을 사용한다. 공식 게임 로고는 사용하지 않는다. 파일은 `assets/icons/organizations/`에 있다. 기관명이 바로 옆에 있어 아이콘은 장식용 빈 대체 텍스트로 처리한다.

## 조직별 확장

아래는 **작성 예시**이며 실제 봉누도 조직·규칙을 추가한 것이 아니다. 추가 속성은 `details`에 Markdown으로 작성한다. 명단 표와 분리되므로 사업체 수, 정원, 득표수 등을 인원으로 잘못 세지 않는다.

```liquid
{% capture business_details %}
| 항목 | 내용 |
| --- | --- |
| 서버·시즌 | 봉누도 시즌2 |
| 업종·사업장 | 확인 후 기록 |
| 소유 그룹 | 관련 위키 링크 |
| 설립·인수·양도 | 날짜 · 변경 내용 · 출처 |
| 평판·전문성 조건 | 대상(대표/구성원) · 조건 · 확인일 · 출처 |
{% endcapture %}
{% include wiki-template.html name="사업체명단" title="사업체 이름" icon="business" body=roster details=business_details %}
```

```liquid
{% capture gang_details %}
- 거점: 확인 후 기록
- 정원·설립 조건: 근거 날짜와 출처를 함께 기록
- 소유 사업체: 조직과 사업체 문서를 연결
- 동맹·적대 관계: 상대 조직 / 관계 / 시작·종료일 / 출처
- 해산·합병·양도: 사건 기록 링크
{% endcapture %}
{% include wiki-template.html name="갱단명단" title="갱단 이름" icon="gang" body=roster details=gang_details %}
```

```liquid
{% capture party_details %}
- 활동 서버·시즌: 확인 후 기록
- 강령·공약: 출처 링크
- 후보·선거: 선거명 / 선거일 / 후보 / 결과 / 출처
- 연정·지지·탈당: 시점별 기록
{% endcapture %}
{% include wiki-template.html name="정당명단" title="정당 이름" icon="party" body=roster details=party_details %}
```

## 조사 메모와 설계 근거 (2026-09-15)

### 확인된 자료

- **봉누도1:** 저장소 `_wiki/wiki-nambong-island-1.md`에는 새부리당·시민의 힘·더불어봉누당의 시점 기록이 있다. 이를 근거로 정당 틀을 지원하되, 시즌1 조직을 시즌2에 자동 복사하지 않는다. 정치 참여와 절차를 다룬 [학술 논문 초록](https://www.kci.go.kr/kciportal/landing/article.kci?arti_id=ART003267512)도 검색에서 확인했다.
- **봉누도2:** [공식 평판 문서](https://bongnudo.super.site/평판)는 평판과 시민 등급, 그룹 설립·유지 조건을 설명한다. [갱단 문서](https://bongnudo.super.site/갱단)는 설립·가입 조건과 최대 소속 인원을 따로 설명한다. 두 문서의 설립 평판 설명에는 차이가 있으므로 실제 적용 조건은 최신 공지 확인이 필요하다. 템플릿에서 자동으로 가입 가능 여부를 판정하지 않는다.
- **조직과 소유 사업체 구분:** [공식 불법 사업체 문서](https://bongnudo.super.site/불법-사업체)는 갱단의 사업체 인수와 인원·평판 조건을 별도로 설명한다. 조직과 사업체를 분리하고 소유 관계를 연결해야 직원 명단과 갱단 명단이 뒤섞이지 않는다.
- **다른 FiveM RP 구현:** [QBCore 공식 문서의 Jobs·Gangs](https://github.com/qbcore-framework/qb-docs/blob/main/qb-core/shared.md)는 직업과 갱단 모두에 가변적인 직급 목록을 둔다. [플레이어 데이터](https://github.com/qbcore-framework/qb-docs/blob/main/qb-core/player-data.md)는 직업과 갱단 소속을 별도로 보관한다. 이는 직급을 공통 틀에 고정하지 않고 복수 조직 소속을 허용하는 설계의 참고이며, 봉누도가 QBCore를 사용한다는 뜻은 아니다.

공식 위키는 직접 접근 시 HTTP 403이어서 검색 색인에 노출된 본문(문서 수정일 2026-09-12)을 참고했다. 나무위키 Chrome 접근은 도구의 사이트 보안 정책으로 차단되어 직접 열람하지 못했다. 봉누도2 정당의 게임 내 기능·자격 요건은 이번 조사에서 확인하지 못했다. 정당 틀은 향후 RP 기록용 구조로만 제공한다.

### 다음 단계 제안

1. 조직마다 안정적인 문서 ID, 서버·시즌, 활동 시작·종료일을 두고 명칭 변경은 별칭으로 연결한다.
2. 현재 명단과 날짜별 변경 기록을 분리한다. 탈퇴자·전임자도 사건 기록에서 찾을 수 있게 한다.
3. 평판, 정원, 인수 조건에는 대상과 기준일·출처를 필수로 기록한다. 시즌 변화가 잦으므로 규칙은 공통 코드에 넣지 않는다.
4. 소유 사업체, 동맹, 적대, 연정 등은 방향·기간이 있는 관계로 기록한다. 단순히 같은 조직 분류로 합치지 않는다.
5. 명단이 커지면 캐릭터별 고유 ID를 도입해 같은 방송인의 시즌별 캐릭터와 동명이인을 구분한다. 현재는 Markdown의 RP 이름 단위 중복 검사를 사용한다.
